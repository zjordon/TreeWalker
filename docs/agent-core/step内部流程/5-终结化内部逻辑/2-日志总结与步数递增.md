# 2-日志总结与步数递增

> 源码位置: `src/tree_walker/agent/step.py` 第 650-666 行

## 📋 方法作用

输出步骤完成日志（耗时、成功/失败计数），然后递增步数计数器。步数递增放在最后，确保所有消费者使用当前值。

## 🔄 主要逻辑流程

```
_finalize() (L650-651)
  │
  ├── _log_step_completion_summary(results)          (L650)
  │     ├── duration = time.time() - _step_start_time
  │     ├── ok = sum(1 for r in results if not r.error)
  │     ├── errs = len(results) - ok
  │     └── log_step_completion(step, duration, ok, errs, logger)
  │
  └── state.n_steps += 1                              (L651) ← 最后执行
```

## 🔍 详细步骤说明

### 1. _log_step_completion_summary (step.py L653-666)

```python
def _log_step_completion_summary(self, results):
    if not results: return
    duration = time.time() - self._step_start_time
    ok = sum(1 for r in results if not r.error)
    errs = len(results) - ok
    log_step_completion(
        step=self.state.n_steps,
        duration=duration,
        ok_count=ok,
        err_count=errs,
        logger=logger,
    )
```

输出步骤耗时和成功/失败计数的结构化日志。

### 2. n_steps 递增 (step.py L651)

```python
self.state.n_steps += 1
```

**为什么放在最后**：
- `_finalize()` 中的 `AgentHistory` 和 `StepEndEvent` 都使用递增前的步号
- 递增后，`run()` 主循环的 `while self.state.n_steps <= self.max_steps` 才能看到新值
- 这保证了所有消费者（历史记录、事件、日志）使用的步号一致

## 🎯 设计亮点

1. **延迟递增** — n_steps 在所有记录操作完成后才 +1，保证步号一致性
2. **空结果保护** — results 为空时跳过日志
