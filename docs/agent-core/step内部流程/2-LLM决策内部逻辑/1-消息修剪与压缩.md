# 1-消息修剪与压缩

> 源码位置: `src/tree_walker/agent/step.py` 第 298 行 (_get_next_action 内)
> 修剪方法: step.py 第 324-338 行
> 压缩方法: `src/tree_walker/agent/message_compactor.py` 第 38-106 行

## 📋 方法作用

在发送给 LLM 之前，控制消息列表长度：(1) 基本修剪保留最近 N 条；(2) 如果启用压缩器，通过 LLM 将旧消息压缩为摘要。

## 🔄 主要逻辑流程

```
_get_next_action() (L298)
  │
  ├── trimmed = self._trim_messages()             (L298)
  │     │
  │     ├── _compactor 存在?
  │     │   ├── Yes → 检查硬安全限制 (3×max_messages)
  │     │   │         └── 超限 → 截断尾部
  │     │   └── No → 截断到最近 max_messages 条
  │     │
  │     └── return list(trimmed)
  │
  └── 在 _step() 编排器中调用压缩 (L86-87)
        └── await self._compactor.maybe_compact(self.messages, self.state.n_steps)
              ├── 门控 1: steps_since < compact_every_n_steps → return
              ├── 门控 2: total_chars < trigger_char_count → return
              ├── _generate_summary() → LLM 压缩
              └── 替换: [first, summary_msg, *tail(keep_last_items)]
```

## 🔍 详细步骤说明

### 1. _trim_messages (step.py L324-338)

```python
def _trim_messages(self, max_messages=20):
    if self._compactor:
        # 压缩器管理修剪，但强制硬安全限制
        if len(self.messages) > max_messages * 3:
            return list(self.messages[-(max_messages * 3):])
        return list(self.messages)
    # 无压缩器 → 保留最近 max_messages 条
    if len(self.messages) <= max_messages:
        return list(self.messages)
    return list(self.messages[-max_messages:])
```

**两种模式**：
- **有压缩器** — 压缩器负责修剪，trim 只做 3× 安全上限兜底
- **无压缩器** — 直接保留最近 20 条消息

### 2. maybe_compact (message_compactor.py L38-106)

双门控检查后执行压缩：

```
maybe_compact(messages, step_number)
  ├── 门控 1: steps_since = step_number - _last_compaction_step
  │   └── < compact_every_n_steps (默认 10) → return
  │
  ├── 门控 2: total_chars = sum(msg.content length)
  │   └── < trigger_char_count (默认 40000) → return
  │
  ├── 构建压缩输入
  │   ├── <previous_compacted_memory> (如果有)
  │   └── <conversation_history>
  │
  ├── _generate_summary() → 调用压缩 LLM
  │
  └── 替换消息列表: [first, summary_msg, *tail(N)]
      └── _last_compaction_step = step_number
```

## 🎯 设计亮点

1. **双门控** — 步数间隔 + 字符数，避免频繁调用压缩 LLM
2. **安全上限** — 即使压缩器启用，3×max_messages 的硬限制防止内存溢出
3. **增量压缩** — 新摘要包含前一次压缩结果，保持上下文连续性
