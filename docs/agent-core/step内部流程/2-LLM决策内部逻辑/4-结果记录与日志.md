# 4-结果记录与日志

> 源码位置: `src/tree_walker/agent/step.py` 第 325-360 行

## 📋 方法作用

LLM 返回决策后，完成三项记录工作：(1) 发射 ModelResultEvent；(2) 将 LLM 响应摘要追加为 assistant 消息；(3) 输出结构化日志。

## 🔄 主要逻辑流程

```
_get_next_action() (L325-360)
  │
  ├── 1. 发射 ModelResultEvent                      (L325-333)
  │     └── {step, session_id, model_call_id, action_name, next_goal}
  │
  ├── 2. 追加 assistant 消息                         (L336-343)
  │     └── {"role": "assistant", "content": "[eval] Goal: xxx | Action: xxx"}
  │
  ├── 3. 结构化日志                                  (L346-357)
  │     └── log_response(evaluation, memory, goal, action, step)
  │
  └── 保存 model_call_id                            (L359)
```

## 🔍 详细步骤说明

### 1. ModelResultEvent (step.py L325-333)

```python
if self._obs_bus:
    self._obs_bus.emit(ModelResultEvent(
        step=self.state.n_steps,
        session_id=self._obs_session_id,
        model_call_id=model_call_id,
        action_name=action.get("name", "done"),
        next_goal=response.get("next_goal", ""),
    ))
```

将 LLM 决策结果通知可观测性系统，用于 JSONL 录制、指标聚合和 TUI 事件显示。

### 2. assistant 消息 (step.py L336-343)

```python
self.messages.append({
    "role": "assistant",
    "content": (
        f"[{response.get('evaluation_previous_goal', '')}] "
        f"Goal: {response.get('next_goal', '')} | "
        f"Action: {response.get('action', {}).get('name', 'unknown')}"
    ),
})
```

将 LLM 的决策摘要追加到对话历史，确保后续步骤的 `messages` 列表保持 user/assistant 交替结构。

### 3. 结构化日志 (step.py L346-357)

```python
log_response(
    evaluation=response.get("evaluation_previous_goal", ""),
    memory=response.get("memory", ""),
    next_goal=response.get("next_goal", ""),
    action_name=action_name,
    action_params=action_params,
    step=self.state.n_steps,
    logger=logger,
)
```

输出四行结构化日志块（由 `log_formatter.py` 格式化），包含评估、记忆、目标、动作名称和参数。

## 🎯 设计亮点

1. **三路同步记录** — EventBus + messages + 日志，分别服务可观测性、LLM 上下文和开发者调试
2. **摘要而非原文** — assistant 消息只保留评估+目标+动作名，不包含完整 JSON，节省 token
