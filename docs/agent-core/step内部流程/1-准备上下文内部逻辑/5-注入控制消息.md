# 5-注入控制消息

> 源码位置: `src/tree_walker/agent/step.py` 第 185-278 行

## 📋 方法作用

在状态消息之后，根据 Agent 运行状态注入三种控制消息，引导 LLM 在特定条件下调用 done 动作：(1) 步数预算警告、(2) 最后一步强制 done、(3) 连续失败强制 done。

## 🔄 主要逻辑流程

```
_prepare_context() (L185-191)
  │
  ├── _inject_budget_warning()              (L185)
  │     └── if steps_used/max_steps >= 75% → 注入预算警告
  │
  ├── _force_done_on_last_step()            (L188)
  │     └── if n_steps >= max_steps-1 → 强制 done-only schema
  │
  └── _force_done_after_failure()           (L191)
        └── if failures >= max_failures → 强制 done-only schema
```

## 🔍 详细步骤说明

### 1. _inject_budget_warning (step.py L229-244)

当已使用步数占总步数的 **≥75%** 时注入警告：

```python
def _inject_budget_warning(self):
    steps_used = self.state.n_steps + 1        # 包含当前步
    budget_ratio = steps_used / self.max_steps
    if budget_ratio >= 0.75 and self.state.n_steps < self.max_steps:
        msg = (
            f"BUDGET WARNING: You have used {steps_used}/{self.max_steps} steps "
            f"({pct}%). {steps_remaining} steps remaining. "
            f"If the task cannot be completed in the remaining steps, "
            f"prioritize consolidating your results and call done. "
            f"Partial results are far more valuable than exhausting all steps with nothing saved."
        )
        self.messages.append({"role": "user", "content": msg})
```

**设计意图** — 提前警告 LLM 步数即将耗尽，鼓励保存部分结果而非浪费剩余步骤。

### 2. _force_done_on_last_step (step.py L246-259)

当 `n_steps >= max_steps - 1` 时（最后一步），**强制切换为 done-only schema**：

```python
def _force_done_on_last_step(self):
    if self.state.n_steps >= self.max_steps - 1:
        msg = (
            "LAST STEP: You have reached max_steps - this is your final step. "
            'You must call the "done" action now. '
            "Summarize what you have accomplished so far."
        )
        self.messages.append({"role": "user", "content": msg})
        self._tool_schema = self.tools.registry.get_tool_schema(
            include_actions=["done"],        # ← 只保留 done 动作
            output_mode=self._output_mode,
        )
```

**关键机制** — 不仅注入消息，还**替换 tool schema** 为只包含 `done` 动作的版本，LLM 别无选择只能调用 done。

### 3. _force_done_after_failure (step.py L261-277)

当 `consecutive_failures >= max_failures` 时，同样强制 done-only schema：

```python
def _force_done_after_failure(self):
    if self.state.consecutive_failures >= self.max_failures:
        msg = (
            f"FAILURE LIMIT: You have failed {self.state.consecutive_failures} "
            f"consecutive times. The agent will terminate after this step. "
            'You must call the "done" action now with whatever results you have.'
        )
        self.messages.append({"role": "user", "content": msg})
        self._tool_schema = self.tools.registry.get_tool_schema(
            include_actions=["done"],
            output_mode=self._output_mode,
        )
```

## 🎯 设计亮点

1. **渐进式控制** — 75% 警告 → 最后一步强制 → 失败上限强制，层层递进
2. **schema 级强制** — 不只是文本提示，而是从 tool schema 层面限制 LLM 只能调用 done
3. **部分结果保护** — 预算警告强调"Partial results are far more valuable"

## 📊 控制消息对比

| 条件 | 消息级别 | schema 变更 | LLM 行为 |
|------|---------|------------|---------|
| ≥75% 步数 | WARNING | 不变 | 建议保存结果 |
| 最后一步 | LAST STEP | done-only | 必须调用 done |
| 连续失败上限 | FAILURE LIMIT | done-only | 必须调用 done |
