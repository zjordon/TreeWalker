## 1. 测试策略

遵循 `CLAUDE.md`：用 `uv run python -m pytest tests/ -x -v`，覆盖率目标 >85%，新增功能必须同步加测试（正常路径 + 关键边界）。

### 1.1 单元测试清单

| 模块 | 关键用例 |
|------|---------|
| **`_finalize` 投影**（02） | 单动作 index 正确投影；多动作等长按位对应；无 index 动作（done/scroll）记 None；空 selector_map 整体 None；`step_interval` = 上一步耗时（首步 None） |
| **`_update_action_indices`**（03） | 五级各命中（构造 selector_map 让某级唯一匹配）；EXACT 命中即不降级；全失败返回 None + 诊断信息正确；`element_id` 别名写回；index 未变时不打日志 |
| **save/load 往返**（01） | `save_to_file`→`load_from_file` 数据等价；脱敏只过滤 input 类、`result` 保留；注册表版本号写入与校验；老格式（无 `interacted_element`）兼容补 None |
| **`_substitute_in_dict`**（05） | 精确整串替换命中；**子串不应被替换**（`"John"` 不动 `"John Doe"`）；只改 params、不动 `interacted_element`/`result`；list 内字符串替换 |

| **`_generate_rerun_summary`**（06） | Layer 1 结构化正常；Layer 1 抛错→Layer 2 文本；Layer 2 抛错→Layer 3 纯计数；`success=(error_count==0)` 计数口径 |

### 1.4 端到端验证标准

**录制一次表单提交 → 换数据重放成功**：
1. 对一个稳定的测试表单页跑 `agent.run()` + `save_history`；
2. `detect_variables()` 发现预期字段（至少 email/name 之一）；
3. `load_and_rerun(variables={换新值})` 重放，所有非 extract 动作通过五级匹配重定位成功；
4. 最终摘要 `success=True`，`extracted_content` 含新值对应的提取结果。

## 3. 关键陷阱清单

迁移自 browser-use 技术分析第 11 节，按 TreeWalker 实情修订：

### ⚠️ 陷阱 1：`step_interval` 语义
存的是**上一步的耗时**（含 LLM 时间），不是当前步。重放必须 `max_step_interval` 封顶，且建议设小（1–5s）。否则会把第一次的 LLM 等待时间又空等一遍。

### ⚠️ 陷阱 2：`stable_hash` 单一数据源
保存端和匹配端必须用**同一套**过滤规则。TreeWalker 里两端都调 `EnhancedDOMTreeNode.compute_stable_hash()`（`browser/views.py:547`，节点方法），天然满足——**切勿在匹配端另写一套**，否则永远匹配不上。

### ⚠️ 陷阱 3：action 是 dict → 无需 `output_model`，但要版本号
反序列化不用重建 ActionModel（dict 直接可用），但须用 `action_registry_version` 防**动作集合漂移**（旧历史里的 action 名在新版不存在）。load 侧宽松校验（warning）+ 重放遇未知动作给可读错误。

### ⚠️ 陷阱 4：无截图 → 摘要语义改写
`RerunSummaryAction.success` 从 browser-use 的「视觉判定」改为「执行证据判定」。prompt **不含图像**，只传 task + 统计 + 文字证据。已知代价：无法发现「动作没报错但页面渲染异常」的视觉问题。

### ⚠️ 陷阱 5：变量替换仅精确整串
`_substitute_in_dict` 用 `value in replacements`，是**整串相等**非子串包含。检测时必须拿到完整值（故只看 `text`/`query`）。误以为是子串替换会导致替换不生效或误伤。

### ⚠️ 陷阱 6：`extract` 重算的 token 成本
重放时每个 `extract` 调一次 LLM 且发当前页 markdown。页面大、extract 多时成本不可忽视。建议 `extract_llm` 用便宜模型（TreeWalker 已支持 `AgentSettings.extract_llm` 独立配置）。

### ⚠️ 陷阱 7：确定性 hash 是增强但别滥用 EXACT
TreeWalker 的 `element_hash`（`__hash__`，sha256）跨会话稳定（优于 browser-use 的随机化 `hash()`），但 EXACT 仍比 STABLE 更易受 `:focus`/`:hover` 动态类影响。**实战以 STABLE 为主力**，EXACT 命中是锦上添花。底线：至少实现 STABLE + AX_NAME + ATTRIBUTE 三级。

### ✅ 已确认的简化（落地时无需再验证）
- **`_action_extract` 自包含**（`tools/actions.py:926`）：内部 `browser.get_page_html()` 读当前页 + `self._extract_llm.extract(...)`，不依赖决策上下文 → 重放直接 re-execute 即在当前页重算，无需 browser-use 的 `_execute_ai_step`。
- **`Tools.execute` 缓存 browser_state**（`actions.py:392`）：handler 签名是 `(params, browser)`，通过 `self._cached_browser_state` 取 selector_map → 重放调 `tools.execute(name, params, browser, fresh_state)` 即可。
