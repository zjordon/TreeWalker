# 03 · 五级元素匹配

> 目标：重放时，页面是动态的——第一次点的 `index=5`，重放时可能变成 `index=8`。本节定义「用历史里录下的元素特征，在当前页 selector_map 里找回同款元素，并更新动作的 `params["index"]`」的算法。

这是整个重放的**核心技术**，直接决定重放成败。

## 1. 算法定位

新增 `StepPipeline._update_action_indices`（或 `Agent` 方法），对齐 browser-use `service.py:3528`，但适配 TreeWalker 的数据形态：

| 维度 | browser-use | TreeWalker |
|------|-------------|------------|
| 历史元素 | `DOMInteractedElement` 对象 | `dict`（`DOMInteractedElement.to_dict()` 产物，见 01） |
| 当前页元素集 | `selector_map: dict[int, EnhancedDOMTreeNode]` | **同**（`dom_state.selector_map`） |
| 动作对象 | Pydantic `ActionModel`（`get_index`/`set_index`） | **dict**（`action["params"]["index"]`） |

**签名**：

```python
def _update_action_indices(
    self,
    historical_elem: dict[str, Any] | None,   # 历史 interacted_element[i]
    action: dict[str, Any],                    # {"name","params"}
    selector_map: dict[int, EnhancedDOMTreeNode],
) -> dict[str, Any] | None:
    """在当前 selector_map 里找回同款元素，更新 params["index"]。

    返回更新后的 action（深拷贝，避免污染历史）；匹配失败返回 None。
    """
```

## 2. 五级降级策略

按优先级逐级尝试，命中即停：

```
Level 1: EXACT     ← element_hash 完全相等
   ↓ 失败
Level 2: STABLE    ← stable_hash 相等（调当前节点 compute_stable_hash()）
   ↓ 失败
Level 3: XPATH     ← x_path 字符串相等
   ↓ 失败
Level 4: AX_NAME   ← node_name + ax_name 相等
   ↓ 失败
Level 5: ATTRIBUTE ← node_name + name/id/aria-label 相等
   ↓ 失败
返回 None → 抛 "Could not find matching element"
```

### Level 1: EXACT（element_hash）

```python
for idx, elem in selector_map.items():
    if elem.element_hash == historical_elem["element_hash"]:
        return _with_index(action, idx, MatchLevel.EXACT)
```

### Level 2: STABLE（重放首选）

```python
hist_stable = historical_elem.get("stable_hash")
if hist_stable is not None:
    for idx, elem in selector_map.items():
        if elem.compute_stable_hash() == hist_stable:
            return _with_index(action, idx, MatchLevel.STABLE)
```

### Level 3: XPATH

```python
hist_xpath = historical_elem.get("x_path")
if hist_xpath:
    for idx, elem in selector_map.items():
        if elem.xpath == hist_xpath:
            return _with_index(action, idx, MatchLevel.XPATH)
```

### Level 4: AX_NAME（动态 SPA 救星）

```python
hist_ax = historical_elem.get("ax_name")
if hist_ax:
    hist_name = historical_elem["node_name"].lower()
    for idx, elem in selector_map.items():
        elem_ax = elem.ax_node.name if elem.ax_node and elem.ax_node.name else None
        if elem.node_name.lower() == hist_name and elem_ax == hist_ax:
            return _with_index(action, idx, MatchLevel.AX_NAME)
```

按「标签类型 + 可访问性名称」匹配，如 `<button>提交</button>` 靠 "提交" 找回。**对动态生成的菜单/下拉特别有效**——菜单项 DOM 结构每次都变，但按钮文字通常稳定。

### Level 5: ATTRIBUTE（兜底）

```python
hist_attrs = historical_elem.get("attributes") or {}
hist_name = historical_elem["node_name"].lower()
for attr_key in ["name", "id", "aria-label"]:        # 优先级顺序
    if hist_attrs.get(attr_key):
        target = hist_attrs[attr_key]
        for idx, elem in selector_map.items():
            if (elem.node_name.lower() == hist_name
                and (elem.attributes or {}).get(attr_key) == target):
                return _with_index(action, idx, MatchLevel.ATTRIBUTE)
```

### `_with_index`（更新 index）

```python
def _with_index(action: dict, new_index: int, level: MatchLevel) -> dict:
    new_action = copy.deepcopy(action)
    params = new_action.get("params", {})
    old = params.get("index")
    # element_id 是 index 的别名；统一写回 index（见 tools/actions.py:530）
    if "element_id" in params and "index" not in params:
        params["element_id"] = new_index
    else:
        params["index"] = new_index
    if old != new_index:
        logger.info("Element index updated %s → %s (matched at %s)",
                    old, new_index, level.name)
    return new_action
```

## 3. TreeWalker 的确定性 hash 是一项**增强**

⚠️ 这点与 browser-use **不同**，落地时务必理解：

| 实现 | `element_hash` 来源 | 跨会话稳定性 |
|------|---------------------|--------------|
| browser-use | Python `hash(node)`（3.3+ 默认 `PYTHONHASHSEED` 随机化） | ❌ 必失败，EXACT 级形同虚设 |
| TreeWalker | `__hash__` → sha256（`browser/views.py:566`） | ✅ **确定性，跨会话稳定** |

也就是说，TreeWalker 的 **EXACT 级在跨会话重放里真的有效**——这是个增强。但 EXACT 仍比 STABLE 更易受 `:focus`/`:hover` 等动态类影响（`__hash__` 保留 `class` 原样，`compute_stable_hash` 过滤动态类，见 `browser/views.py:547 vs :566`）。所以五级顺序保持 EXACT→STABLE 仍合理，但**实战中 STABLE 才是主力**。

**单一数据源原则（关键陷阱）**：`stable_hash` 必须在**保存端**和**匹配端**用同一套算法。TreeWalker 里两端都调 `EnhancedDOMTreeNode.compute_stable_hash()`（同一个节点方法），天然满足——**切勿在匹配端另写一套过滤规则**，否则永远匹配不上。

## 4. 匹配失败诊断

全失败时返回 None，由调用方（04 §单步执行）抛出可读错误。错误信息应包含（仿 browser-use `_format_element_for_error` `service.py:3679`）：

- 目标元素：`<node_name>` + 关键属性 + hash + xpath
- 当前页 selector_map 元素总数
- 同类型元素的可用 aria-label 列表（前 5 个）

示例：

```
Could not find matching element for action 0 in current page.
  Looking for: <BUTTON> name="submit" hash=1234567890 xpath="html/body/.../button"
  Page has 87 interactive elements.
  Available <BUTTON> with aria-label: [3:'Cancel', 7:'Save', 12:'Submit Form']
  Tried: EXACT → STABLE → XPATH → AX_NAME → ATTRIBUTE
```

## 5. 五级稳定性对比（按 TreeWalker 修订）

| 级别 | 匹配 key | 跨会话稳定 | 抗 DOM 变化 | 适用场景 |
|------|----------|------------|-------------|----------|
| EXACT | `element_hash` | ✅（TreeWalker 增强） | ❌（受动态类影响） | 同结构页面，备选 |
| **STABLE** | `stable_hash` | ✅ | ⚠️ 中 | **重放首选**，大多数情况 |
| XPATH | `x_path` | ✅ | ❌（列表增减即失效） | 静态页面 |
| AX_NAME | node_name + ax_name | ✅ | ✅ | **动态菜单/SPA 救星** |
| ATTRIBUTE | name/id/aria-label | ✅ | ⚠️ 中 | 老历史文件兜底 |

**底线**：至少实现 STABLE + AX_NAME + ATTRIBUTE 三级，才能覆盖大多数真实场景。只实现一级会大面积失败（列表增减→XPATH 失效；焦点态变化→EXACT 失效；动态菜单→DOM 结构每次不同需 AX_NAME）。

## 6. `MatchLevel` 枚举

```python
class MatchLevel(Enum):

    STABLE = 2
    XPATH = 3
    AX_NAME = 4
    ATTRIBUTE = 5
```
