# 04 · 重放执行器

> 目标：读入历史，按录好的动作序列驱动浏览器重跑——不调决策 LLM（`extract` 除外），用 03 的五级匹配重定位元素，用 `tools.execute` 真实执行。

## 1. 主流程 `rerun_history`

对齐 browser-use `service.py:3102`，加到 `Agent`（建议放新 mixin `agent/rerun.py`，由 `Agent` 继承）。

```python
async def rerun_history(
    self,
    history: AgentHistoryList,
    *,
    max_retries: int = 3,
    skip_failures: bool = False,
    delay_between_actions: float = 2.0,
    max_step_interval: float = 45.0,
    wait_for_elements: bool = False,
    summary_llm: LLMClient | None = None,
    ai_step_llm: LLMClient | None = None,
) -> list[ActionResult]:
    """重放保存好的历史。返回 list[ActionResult]，最后一项是 AI 摘要（is_done=True）。"""
    await self.browser.start(track_downloads=self._track_downloads)

    # 1. 重导航初始 URL（见 §2）
    await self._rerun_initial_navigation(history)

    results: list[ActionResult] = []
    previous_item: AgentHistory | None = None
    previous_succeeded = False

    try:
        for history_item in history.history:
            # 2. 步间延迟（见 §3）
            step_delay = self._compute_step_delay(history_item, delay_between_actions, max_step_interval)

            # 3. 跳过检查（见 §4：无动作/原始出错/冗余重试）
            if self._should_skip(history_item, previous_item, previous_succeeded, skip_failures):
                previous_item, previous_succeeded = history_item, False
                continue

            # 4. 重试循环（指数退避，见 §4）
            step_results = await self._rerun_step_with_retries(
                history_item, step_delay, max_retries,
                previous_item, ai_step_llm, wait_for_elements,
            )
            results.extend(step_results)
            previous_succeeded = not any(r.error for r in step_results)
            previous_item = history_item

            if any(r.is_done for r in step_results):
                break
    finally:
        # 5. 最终 AI 摘要（见 06）
        summary = await self._generate_rerun_summary(self.task, results, summary_llm)
        results.append(summary)
        await self.browser.stop()

    return results
```

## 2. 重导航初始 URL

复用 `Agent._extract_url` + `browser.navigate`（`run()` 同款，`agent.py:200`）。来源优先级：历史首步的 `state_summary.url` → 从 `task` 抽取。

```python
async def _rerun_initial_navigation(self, history: AgentHistoryList) -> None:
    initial_url = None
    if history.history:
        initial_url = (history.history[0].state_summary or {}).get("url")
    if not initial_url:
        initial_url = self._extract_url(self.task)
    if initial_url:
        try:
            await self.browser.navigate(initial_url)
        except Exception as e:
            logger.warning("Failed to navigate to initial URL: %s", e)
```

> 录制时第一步若含 `navigate` 动作，重放会再点一次——无副作用（导航到同 URL）。

## 3. 步间延迟（关键调优点）

```python
def _compute_step_delay(self, item, delay_between_actions, max_step_interval) -> float:
    if item.metadata and item.metadata.step_interval is not None:
        # 封顶：step_interval 含上一步的 LLM 时间，重放不需要等那么久
        return min(item.metadata.step_interval, max_step_interval)
    return delay_between_actions
```

⚠️ **`step_interval` 语义陷阱**：它存的是**上一步的耗时**（含 LLM 决策时间，见 02 §2.2）。第一次运行某步 LLM 可能花 20s，那么下一步记录的 `step_interval`≈20s。重放若不封顶，会把这个 LLM 等待时间又「空等」一遍。

**调优建议**：
- `max_step_interval`（默认 45s）：重放不调决策 LLM，压到 **1–5s** 即可。
- `delay_between_actions`（默认 2s）：无保存间隔时的兜底，可压到 0.5–1s。
- browser-use 示例用 `max_step_interval=20, delay_between_actions=1`。

## 4. 五种跳过/重试策略

| 策略 | 触发 | 行为 |
|------|------|------|
| **无动作跳过** | `actions` 为空或全 None | 记 warning，跳过 |
| **原始出错跳过** | 该步首次运行就报错（`skip_failures=True`） | 跳过，避免重蹈覆辙 |
| **冗余重试跳过** | 与上一步同元素同动作类型且上步已成功 | 跳过（页面已翻，再点会失败） |
| **菜单重打开** | 找不到元素 + 上一步是菜单 opener | 重打开下拉再重试，**不消耗 retry** |
| **指数退避重试** | 步骤执行抛异常 | 5s→10s→20s（cap 30s）重试，达 `max_retries` 报错 |

### 4.1 冗余重试跳过 `_is_redundant_retry_step`

首次运行页面慢可能重复点同一元素；重放时第一次就成功、页面已翻，后续重复点会找不到元素。判定（三选一判定「同一元素」+ 同动作类型）：

```python
def _is_redundant_retry_step(self, curr, prev, prev_succeeded) -> bool:
    if not prev or not prev_succeeded:
        return False
    curr_elems = curr.interacted_element or []
    prev_elems = prev.interacted_element or []
    if not curr_elems or not prev_elems:
        return False
    c, p = curr_elems[0], prev_elems[0]
    if not c or not p:
        return False
    same = (c.get("element_hash") == p.get("element_hash")
            or c.get("stable_hash") == p.get("stable_hash")
            or c.get("x_path") == p.get("x_path"))
    if not same:
        return False
    curr_type = (curr.model_output.get("action") or curr.model_output.get("actions", [{}])[0]).get("name")
    prev_type = (prev.model_output.get("action") or prev.model_output.get("actions", [{}])[0]).get("name")
    return curr_type == prev_type
```

### 4.2 菜单重打开（SPA 场景）

下拉菜单在步骤等待期间可能自动关闭，导致菜单项找不到。检测到这种失败时，重执行上一步（菜单 opener）再重试，**不消耗 retry 次数**：

```python
if "Could not find matching element" in error_str and self._is_menu_opener_step(previous_item):
    if await self._reexecute_menu_opener(previous_item, ai_step_llm):
        retry_count -= 1           # 不消耗 retry
        step_delay = 0.5           # 短延迟后立即重试
        continue
```

菜单 opener 识别靠属性特征：`aria-haspopup`、`data-gw-click="toggleSubMenu"`、`expand-button` class、`role=button`+`aria-expanded` 等（移植 browser-use `service.py:3775`）。

### 4.3 指数退避

```python
backoff = min(5 * (2 ** retry_count), 30)   # 5 → 10 → 20, cap 30
await asyncio.sleep(backoff)
```

## 5. 单步执行 `_execute_history_step`

每步先取**当前** selector_map，再遍历动作分流执行（仿 browser-use `service.py:3397`）：

```python
async def _execute_history_step(self, item, delay, ai_step_llm, wait_for_elements) -> list[ActionResult]:
    await asyncio.sleep(delay)

    # 可选：SPA 等待元素达到预期数量（见 §6）
    state = await self.browser.get_state(include_screenshot=False)
    if wait_for_elements:
        state = await self._wait_for_minimum_elements(state, item, timeout=15.0)

    selector_map = state.dom_state.selector_map if state.dom_state else {}
    actions = item.model_output.get("actions") or [item.model_output.get("action", {})]
    interacted = item.interacted_element or []

    results: list[ActionResult] = []
    pending: list[dict[str, Any]] = []     # 累积非 extract 动作，批量执行保序

    for i, action in enumerate(actions):
        name = action.get("name", "done")
        params = action.get("params", {})

        if name == "extract":
            # extract 前 flush 累积动作（保 [click, extract] 顺序）
            if pending:
                results.extend(await self._exec_batch(pending, state))
                pending = []
            # extract 直接 re-execute：自带 LLM、读当前页（见 §7）
            results.append(await self.tools.execute("extract", dict(params), self.browser, state))
        elif name in _NO_ELEMENT_ACTIONS:   # done/scroll/search/wait/...
            pending.append(action)
        else:
            hist_elem = interacted[i] if i < len(interacted) else None
            updated = self._update_action_indices(hist_elem, action, selector_map)   # 03
            if updated is None:
                raise ValueError(self._format_match_failure(hist_elem, i, selector_map))
            pending.append(updated)

    if pending:
        results.extend(await self._exec_batch(pending, state))
    return results
```

## 6. SPA 等待元素 `wait_for_elements`

对动态加载的 SPA，可选在匹配前轮询等待页面达到预期元素数（按历史 action 的最大 index 推算 `min_elements = max_index + 1`）：

```python
async def _wait_for_minimum_elements(self, state, item, timeout, poll=1.0):
    min_elements = self._count_expected_elements(item)   # max_index + 1
    deadline = time.time() + timeout
    while time.time() < deadline:
        if state.dom_state and len(state.dom_state.selector_map) >= min_elements:
            return state
        await asyncio.sleep(poll)
        state = await self.browser.get_state(include_screenshot=False)
    return state   # 超时也返回当前状态，交给匹配/诊断
```

## 7. extract 重算（TreeWalker 简化）

⚠️ **这是本方案相对 browser-use 的一项关键简化**（见 README 差异表）：

- browser-use 为 extract 单独写了 `_execute_ai_step`（`service.py:2997`），因为它需要重新调 LLM 分析当前页 markdown。
- **TreeWalker 不需要**。`_action_extract`（`tools/actions.py:926`）**本身就自包含**：
  - 读**当前页** HTML：`browser.get_page_html(...)`（`actions.py:936`）；
  - 转 markdown 后调 `self._extract_llm.extract(query, chunk_content, ...)`（`actions.py:970`）；
  - 不依赖任何决策上下文。

所以重放时直接 `tools.execute("extract", {...}, browser, current_state)`，就是在**当前页**用 `_extract_llm` 重算。数据替换后页面内容变了，旧提取结果自然被新结果覆盖——这正是 extract 需要「重算」的本意。

**token 成本提示**：每个 extract 都调一次 LLM 且把当前页 markdown 发过去。页面大、extract 多时成本不可忽视——建议 `ai_step_llm` 用便宜模型（TreeWalker 里 `extract` 已支持独立 `extract_llm`，见 `AgentSettings.extract_llm`）。
