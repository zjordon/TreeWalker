# 06 · AI 摘要（无截图适配）

> 目标：重放结束后，自动判定「这次重放成功了吗」，作为最后一个 `ActionResult(is_done=True)` 返回。
>
> ⚠️ 本方案**无截图**，这是相对 browser-use 最重要的适配点。

## 1. 核心适配：从「视觉判定」改为「执行证据判定」

| 维度 | browser-use | TreeWalker（本方案） |
|------|-------------|----------------------|
| 判定依据 | **截图** + 执行统计 | **纯文本执行证据** + 统计（无截图） |
| `RerunSummaryAction.success` 语义 | "based on **visual inspection**" | "based on **execution evidence**" |
| prompt 输入 | 多模态（image_url + 文本） | 纯文本（task + 统计 + 各步 extracted_content 摘要 + 访问过的 URL） |

**为什么这样改**：本方案决策「完全不要截图」（见 README/01）。失去视觉依据后，摘要 LLM 只能依据：原文 task、成功/失败步计数、各步 `extracted_content` 的文字摘要、访问过的 URL 序列。这足以在大多数「重放是否完成预定动作」的场景下给出合理判定；但无法像截图那样发现「页面渲染异常但动作没报错」这类视觉问题——这是无截图的已知代价。

## 2. 数据模型

```python
from typing import Literal

class RerunSummaryAction(BaseModel):
    summary: str = Field(description="本次重放发生了什么（基于执行证据）")
    success: bool = Field(description="基于执行证据（步成功/失败计数 + 提取内容）判定是否成功")
    completion_status: Literal["complete", "partial", "failed"] = Field(
        description="complete(全成功) / partial(部分成功) / failed(未完成)"
    )
```

## 3. 三层兜底

```
Layer 1: 结构化判定（首选）
   task + 执行证据 → LLMClient.extract(output_schema=RerunSummaryAction) → 解析 JSON
   ↓ 失败（LLM 不支持结构化 / 返回非法 JSON）
Layer 2: 文本兜底
   task + 执行证据 → LLMClient.extract(output_schema=None) → 纯文本 summary
   success = (error_count == 0)
   ↓ 失败（LLM 整体调用失败）
Layer 3: 纯计数兜底（不调 LLM）
   success = (error_count == 0)
   summary = "X/Y steps succeeded"
```

## 4. 实现 `_generate_rerun_summary`

```python
async def _generate_rerun_summary(
    self, original_task: str, results: list[ActionResult],
    summary_llm: LLMClient | None = None,
) -> ActionResult:
    llm = summary_llm or self.llm
    error_count = sum(1 for r in results if r.error)
    success_count = len(results) - error_count

    # 拼装「执行证据」文本（无截图，全靠文字）
    evidence = self._build_rerun_evidence(results)   # 各步 extracted_content 摘要 + 访问过的 URL
    prompt = get_rerun_summary_prompt(
        original_task=original_task,
        total_steps=len(results),
        success_count=success_count,
        error_count=error_count,
        evidence=evidence,
    )

    # Layer 1：结构化（复用 LLMClient.extract 的 output_schema 机制）
    try:
        schema = _rerun_summary_json_schema()        # RerunSummaryAction 的 JSON Schema
        raw = await asyncio.wait_for(
            llm.extract(prompt=prompt, content=evidence, output_schema=schema),
            timeout=120.0,
        )
        summary = RerunSummaryAction.model_validate_json(raw)
    except Exception:
        # Layer 2：文本兜底
        try:
            text = await asyncio.wait_for(
                llm.extract(prompt=prompt, content=evidence, output_schema=None),
                timeout=120.0,
            )
            summary = RerunSummaryAction(
                summary=text,
                success=(error_count == 0),
                completion_status="complete" if error_count == 0
                                  else ("partial" if success_count > 0 else "failed"),
            )
        except Exception:
            # Layer 3：纯计数兜底（不调 LLM）
            summary = RerunSummaryAction(
                summary=f"{success_count}/{len(results)} steps succeeded",
                success=(error_count == 0),
                completion_status="complete" if error_count == 0
                                  else ("partial" if success_count > 0 else "failed"),
            )

    return ActionResult(
        is_done=True,
        success=summary.success,
        extracted_content=summary.summary,
        long_term_memory=f"Rerun completed with status: {summary.completion_status}.",
    )
```

### 4.1 为什么用 `LLMClient.extract` 而非新方法

`LLMClient.extract`（`llm/client.py:313`）已支持：`output_schema` 传 JSON Schema（`type=object` + `properties`）时，**强制走 Anthropic tool 的结构化输出**并返回校验后的 JSON 字符串；传 `None` 时返回自由文本。这正好覆盖 Layer 1（结构化）和 Layer 2（文本），**无需新增 LLM 方法**——这是 TreeWalker 现有能力的直接复用。

> 不要用 `LLMClient.get_action`：它硬编码 `tool_choice={"type":"tool","name":"agent_response"}`（`client.py:187`），是给 agent 决策专用的，不适合任意摘要 schema。

## 5. Prompt（无图像版）

对齐现有 `prompts/system_prompt.py` 风格，明确不传图像、只传文本证据。建议放在 `src/tree_walker/prompts/rerun_summary.py`：

```python
def get_rerun_summary_prompt(*, original_task, total_steps, success_count, error_count, evidence) -> str:
    return f"""你正在分析一次任务重放（rerun）的完成情况。
基于下方【执行证据】（无截图），判断重放是否成功。

原始任务: {original_task}

执行统计:
- 总步数: {total_steps}
- 成功步: {success_count}
- 失败步: {error_count}

执行证据（各步结果摘要 + 访问过的 URL）:
{evidence}

请判断:
1. 任务是否按预期完成
2. 最终状态说明了什么
3. 整体完成度（complete/partial/failed）

返回 JSON:
- summary: 重放发生了什么的清晰摘要
- success: 是否成功（true/false）
- completion_status: complete / partial / failed 之一
""".strip()
```

## 6. `RerunSummaryAction` 的 JSON Schema

供 `extract(output_schema=...)` 使用。可用 `RerunSummaryAction.model_json_schema()` 生成，或手写确保 `type=object`+`properties`（`extract` 的校验要求，`client.py:334`）。

## 7. 输出位置

摘要作为**最后一个** `ActionResult(is_done=True)` 追加到 `rerun_history` 的返回列表。调用方据此判断：

```python
results = await agent.load_and_rerun("history.json", ...)
if results and results[-1].is_done:
    summary = results[-1]
    print(f"Success: {summary.success}")         # True/False
    print(f"Summary: {summary.extracted_content}")
```
