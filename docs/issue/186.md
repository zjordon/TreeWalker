## 现象

同轮评测暴露两条 agent 行为纪律缺口（均导致判 0）：

1. **工具连败不止损、原地发明 workaround**——task 374（B 轮，预览主题任务）：
   agent 为"验证主题预览图"对裸图片 URL 连续 `screenshot` 失败 3 次（无 DOM 的媒体页本就截不了），非但没有止损，反而升级投入：用 `document.write` 把媒体页包成 HTML 再截（又败）→ 再 `fetch` base64 "验证"图片字节可加载——为一个判分根本不看的目标烧掉 6 步 ~2 分钟，且全程停留在错误页面（该任务判分只看最终 URL，agent 此前已站在得分页上）。
2. **数据不完整仍 done 收题**——task 64（B 轮，按客户计数）：
   step 16 的自评明确写着 "Emma Davis=1?**?**"、且自知"中间有 ~60 行未读缺口"，仍然 done(success=True) 收题——计数最终错误判 0。

背景数据：三口径全量中 agent 自评成功率 87~90%（`is_successful`），实际判分 66~73%；剔除全部判分基建误判后的真实"自认成功但判分失败"仍有 A 42 / B 46 / C 34 个任务（eval 仓 `docs/self-overestimate-analysis-2026-09-10.md`）——自评系统性偏高是普遍现象，本 issue 取其中最可执行的两条行为层切入口。

- [ ] **连败止损**：同一工具/手段连续失败 2 次应触发策略干预——放弃该手段、回归任务目标重新规划（优先判分相关的动作），而非在原地发明 workaround
- [ ] **self-verify 纳入数据完整性**：agent 自评中存在未消解的不确定性（未读缺口、计数带 ?）时不应允许以 success=True 结束——要么补齐验证，要么以"数据不完整"如实收题
