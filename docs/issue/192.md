**现象**：`select_dropdown` 作用于 `<select multiple>` 时每次调用**替换**整组选中，
而非累加。699（Cart Price Rule 客户组）：按卡 quirks"多次调用、每次选一个"操作
General/Wholesale/Retailer 三组，保存后**只剩最后一次的 Retailer**，五查挂三。
700/701 轮 agent 被迫绕行 JS `option.selected` 才成功（轨迹可查）。

**修复方向**（二选一或都做）：
1. `select_dropdown` 增加 `multi: [v1, v2, ...]` 语义，一次设全；
2. 保持替换语义但动作描述与文档明示，并在 skill quirks 里写正确的多选做法
   （逐项 JS `option.selected=true` + change 事件）。

**验收**：699 场景回放——三组选中全部持久化。
证据：分析文档 699/700/701 条目。

## 修复总结评论（2026-09-19，issuecomment-5739478281）

**根因**：`_SELECT_OPTION_JS` 三连写（`element.value=` / `option.selected=` / `element.selectedIndex=`）对 `<select multiple>` 按 HTML 规范全是"先清空再选中"的替换语义，且单次调用后 `element.value === expectedValue` 恒真（getter 只返回第一项）——三次"成功"调用只剩最后一个。叠加 quirks 卡"连续调用 4 次、各传一组"的教法，构成系统性翻车（699 三组客户组保存后只剩 Retailer，五查挂三）。这是 `docs/tools-optimize/select_dropdown_follow_up.md` 风险 6 登记在案的 P2 限制到期，非未知 bug。

**修复**（方案 `docs/bug-fix/192-select-multiple-impl-plan.md` 四模块，issue 两个修复方向都做）：

- **session 层**：新 `_SELECT_OPTION_MULTI_JS`——只用 `option.selected` 整组设置（一次设全、幂等，三条替换路径全禁用）、all-or-nothing（任一值 miss 不写值，回显 missed + availableOptions）、选中集回读验证（multiple 的 `element.value` 只返回第一项不能用作验证）；G11 懒加载重试提取 `_lazy_select_call` 单选/多选共用
- **params/action 层**：`SelectDropdownParams` 增 `values: list[str]`（value 转 Optional + 二选一 validator）；handler 运行时守卫（registry 不校验 execute 路径——同传/皆无/空列表/非 SELECT 四类）；SELECT+values 路由 `set_select_option_multi`
- **模型侧**：DROPDOWN_RULES 第 4 条（multiple 一次设全 + 替换语义警示）+ ACTION 表 description
- **quirks 纠错**：`create-spring-sale-price-rule` 卡第 2 条改写为 values 单次设全，旧教法"连续调用 4 次"废止并注明原因
