# issue #187: 依赖：anthropic SDK 1.4.0 过旧——Messages.create 不支持 temperature，LLM 调用无法显式控温

- 状态：OPEN
- 作者：zjordon
- 创建：2026-09-12T12:40:07Z
- 来源：https://github.com/zjordon/TreeWalker/issues/187

---

## 现象

TreeWalker 依赖锁定的 anthropic SDK 为 **1.4.0（2023 年版本）**，其 `Messages.create` 不支持 `temperature` 参数。eval 仓把 fuzzy_match/ua_match 的 LLM judge 从 OpenAI 切到 GLM（经 `LLMClient._extract_call(..., temperature=0)`）时每次调用抛：

```
TypeError: Messages.create() got an unexpected keyword argument 'temperature'
```

该问题在评测中造成 **22 个 fuzzy_match 任务 × 三口径 = 66 次评测全部判 0**（judge 异常被评测器计 0 静默吞掉，运行期间无一被发现）——含 21 个真实参考答案任务与 1 个 N/A 型（ua_match 路径）。eval 仓已于 2026-09-12 做兼容修复（temperature 优先传、TypeError 降级默认温度重试）并离线重判翻绿（A +14 / B +19 / C +17）。

## 影响

- `LLMClient` 的所有调用方**无法显式控温**：任何需要确定性输出（judge、抽取、结构化输出）的场景只能用模型默认采样温度——eval 仓实测同格式判定存在随机翻转（2026-08-26 记录：8 条判定挂 1-2 条）；
- 新版 SDK 的能力（prompt caching、结构化新参数等）不可用。

## 请求

- [ ] 升级 anthropic SDK 至当前版本（或至少声明已测试的支持范围），使 `temperature` 等基础采样参数可透传
- [ ] 升级时注意 `LLMClient._extract_call` / fallback client 的兼容性（eval 仓的降级兼容逻辑在升级后可自然恢复 judge 确定性）

## 环境

- venv 实测：`anthropic==1.4.0`（`pip show`），`Messages.create` 签名无 `temperature`
- 发现与修复全程：eval 仓 zjordon/treewalker-webarena `docs/skills/shop-admin/harness-optimize.md`（2026-09-12 09:04 条目，含三级证据）与 `cdp_evaluator.py` 兼容修复
