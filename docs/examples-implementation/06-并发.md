## Issue 正文（建 issue 时用）

**标题**：`feat(examples): 并发多 agent（asyncio.gather）—— 移植自 browser-use`

**正文**：
移植 browser-use 的 `parallel_agents` 示例。TreeWalker **不内置并发原语**，并发靠 `asyncio.gather` 跑多个 `Agent`。

**关键 caveat（实施与验证时务必注意）**：多个 `BrowserSession` 连**同一个 Chrome / 同一个 CDP 端口**时，它们共享同一浏览器上下文与标签页空间，会**互相干扰**（标签切换、焦点抢占、DOM 状态串扰）。这和 browser-use 用 `user_data_dir` 起**独立浏览器实例**的隔离完全不同——TreeWalker 不启动浏览器，**没有 `user_data_dir`**。

因此本 issue 提供两种形态：
- **形态 A（默认示例，共享会话）**：同一 Chrome 里并发跑多个独立任务，演示并发写法本身，但**不保证互不干扰**。
- **形态 B（强隔离，文档说明）**：若需真隔离，应为每个并发 agent 启动**独立的 Chrome（各自独立的 `--remote-debugging-port`）**再各自连，而非依赖 TreeWalker 侧配置。

DoD：`uv run` 实跑，3 个任务并发完成并各自打印结果；文档/注释清楚说明隔离 caveat。

### 6.1 `examples/custom-functions/parallel_agents.py`（形态 A：共享会话）

**完整代码**（直接保存为 `examples/custom-functions/parallel_agents.py`）：

```python
"""Example: 并发多 agent（asyncio.gather）。移植自 browser-use/examples/custom-functions/parallel_agents.py。

形态 A（本文件）：多个 BrowserSession 连同一个 Chrome，共享浏览器上下文/标签页空间。
适合演示并发写法，但任务间可能互相干扰（标签切换/焦点）。

【强隔离方案（形态 B）】如需互不干扰，应为每个并发 agent 启动独立的 Chrome
（各自独立的 --remote-debugging-port，例如 9222/9223/9224），再用各自的
BrowserSettings(ws_url=...) / cdp_port 连接。TreeWalker 不启动浏览器、没有
browser-use 的 user_data_dir，无法靠配置实现多实例隔离。
前置：uv sync / chrome --remote-debugging-port=9222 / $env:ZHIPU_API_KEY="..."
运行：uv run python examples/custom-functions/parallel_agents.py
"""
import asyncio
import logging
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[2] / "src"))

from tree_walker import Agent, BrowserSession, LLMClient
from tree_walker.config import load_settings


TASKS = [
	"Go to https://news.ycombinator.com/ and return only the top story title.",
	"Go to https://www.github.com/trending and return only the top repository name.",
	"Go to https://quotes.toscrape.com/ and return only the first quote and its author.",
]


async def run_one(idx: int, task: str, settings) -> None:
	# 每个 agent 用独立 BrowserSession（连同一个 Chrome）
	browser = BrowserSession(settings.browser)
	agent = Agent(
		task=task,
		llm=LLMClient(settings.llm),
		browser=browser,
		settings=settings.agent,
	)
	history = await agent.run()
	done = history.is_done()
	result = history.final_result() or "(no result)"
	print(f"[{idx}] done={done} -> {result}")


async def main() -> None:
	logging.basicConfig(level=logging.INFO)
	settings = load_settings()
	if not settings.llm.api_key:
		print("Error: 请设置 ZHIPU_API_KEY 环境变量")
		sys.exit(1)
	if not settings.browser.ws_url:
		print("Error: 请先用 chrome --remote-debugging-port=9222 启动 Chrome")
		sys.exit(1)

	await asyncio.gather(*(run_one(i, t, settings) for i, t in enumerate(TASKS)))


if __name__ == "__main__":
	asyncio.run(main())
```

**适配注意点**：
- 这是**形态 A**：写法正确，但因共享 Chrome，3 个 agent 操作同一浏览器可能互相踩标签。验证时若出现串扰，属预期（caveat），不是 bug。
- **形态 B（强隔离）实现要点**：先起 3 个 Chrome：
  ```
  chrome --remote-debugging-port=9222 --user-data-dir=<dir1>
  chrome --remote-debugging-port=9223 --user-data-dir=<dir2>
  chrome --remote-debugging-port=9224 --user-data-dir=<dir3>
  ```
  再在 `run_one` 里按 `idx` 选不同 `cdp_port` 构造 `BrowserSettings(cdp_port=9222 + idx)`。本 issue 不强制实现形态 B，但建议在示例注释里保留指引（已在文件头注释给出）。

## 风险 / caveat

- **共享会话串扰**：形态 A 下多 agent 抢同一浏览器，可能出现标签被切走、抓到对方页面等情况。若你的真实场景要求严格隔离，必须走形态 B（多 Chrome 实例）。
- 并发会放大 LLM 限流概率；必要时为每个 agent 配 fallback（见 Issue #3）。
- 本 issue 不涉及 `src/` 改动。
