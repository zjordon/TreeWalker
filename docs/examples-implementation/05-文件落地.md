## Issue 正文（建 issue 时用）

**标题**：`feat(examples): 文件落地（下载文件/生成 CSV）—— 移植自 browser-use`

**正文**：
移植 browser-use 中"把数据落到本机文件"的两类示例，二者落地方式与 browser-use 不同：
- **下载文件**：browser-use 用 `Browser(downloads_path=...)` 指定下载目录；TreeWalker **没有 `downloads_path`** —— 下载文件落地到 **Chrome 自身的下载目录**，无法在 TreeWalker 侧指定。改用 `AgentSettings(track_downloads=True)`，已下载文件作为 `done` 的附件回传；配合 `display_files_in_done_text=True` 可把附件内容内联进 `final_result()`。
- **生成 CSV**：browser-use 用内置 agent file system + 自动 CSV 规范化（`agent.file_system.get_file`）；TreeWalker **没有 agent file system**，改让 agent 用 `write_file` 工具把结构化数据写成 CSV 到一个工作区目录（受 `allowed_write_paths` 白名单约束，仿现有 `examples/file_system/file_system.py`）。

任务清单：

- [ ] `examples/features/csv_generation.py` ← `features/csv_file_generation.py`

DoD：两个文件均可 `uv run` 实跑，分别完成下载（文件落地 + 附件回传）/ 生成 CSV（工作区内出现 .csv）。

### 5.1 `examples/features/download_file.py`

**完整代码**（直接保存为 `examples/features/download_file.py`）：

```python
"""Example: 下载文件（track_downloads）。移植自 browser-use/examples/features/download_file.py。

browser-use 用 Browser(downloads_path=...) 指定下载目录；TreeWalker 没有 downloads_path——
下载文件落地到 Chrome 自身的下载目录，无法在 TreeWalker 侧指定。
开启 track_downloads=True 后，已下载文件作为 done 的附件回传；
配合 display_files_in_done_text=True 可把附件内容内联进 final_result()。
前置：uv sync / chrome --remote-debugging-port=9222 / $env:ZHIPU_API_KEY="..."
运行：uv run python examples/features/download_file.py
（下载到的文件在 Chrome 的默认下载目录里查找，例如 C:/Users/<you>/Downloads）
"""
import asyncio
import logging
import sys
from dataclasses import replace
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[2] / "src"))

from tree_walker import Agent, BrowserSession, LLMClient
from tree_walker.config import load_settings


# 一个稳定可下载的小文件（公共资源）；按需替换为别的可下载直链
TASK = (
	"Go to https://www.w3.org/WAI/ER/tests/xhtml/testfiles/resources/pdf/dummy.pdf "
	"and download the PDF file."
)


async def main() -> None:
	logging.basicConfig(level=logging.INFO)
	settings = load_settings()
	if not settings.llm.api_key:
		print("Error: 请设置 ZHIPU_API_KEY 环境变量")
		sys.exit(1)
	if not settings.browser.ws_url:
		print("Error: 请先用 chrome --remote-debugging-port=9222 启动 Chrome")
		sys.exit(1)

	agent_settings = replace(
		settings.agent,
		track_downloads=True,            # 跟踪下载 → 作为 done 附件回传
		display_files_in_done_text=True, # 把附件内容内联进 final_result()
	)
	llm = LLMClient(settings.llm)
	browser = BrowserSession(settings.browser)
	agent = Agent(task=TASK, llm=llm, browser=browser, settings=agent_settings)
	history = await agent.run()

	print("done:", history.is_done())
	result = history.final_result()
	if result:
		print("\n--- final_result ---")
		print(result)


if __name__ == "__main__":
	asyncio.run(main())
```

**适配注意点 / 验证点**：
- 文件实际落地在 **Chrome 默认下载目录**（如 `C:/Users/<you>/Downloads`），去那里核对是否出现 `dummy.pdf`。
- `final_result()` 里应包含已下载文件的附件信息（路径/大小）；PDF 是二进制，`display_files_in_done_text` 对 PDF 不会把正文内联为文本，但附件元信息仍会回传。
- 若该直链失效，换任意可直接下载的小文件 URL 即可。

### 5.2 `examples/features/csv_generation.py`

**完整代码**（直接保存为 `examples/features/csv_generation.py`）：

```python
"""Example: 生成 CSV。移植自 browser-use/examples/features/csv_file_generation.py。

browser-use 用内置 agent file system + 自动 CSV 规范化（agent.file_system.get_file）；
TreeWalker 没有 agent file system，改为让 agent 用 write_file 工具把结构化数据
写成 CSV 到一个工作区目录（受 allowed_write_paths 白名单约束）。
仿现有 examples/file_system/file_system.py 的 workspace 模式。
前置：uv sync / chrome --remote-debugging-port=9222 / $env:ZHIPU_API_KEY="..."
运行：uv run python examples/features/csv_generation.py
"""
import asyncio
import logging
import shutil
import sys
from dataclasses import replace
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[2] / "src"))

from tree_walker import Agent, BrowserSession, LLMClient
from tree_walker.config import load_settings

SCRIPT_DIR = Path(__file__).resolve().parent
WORKSPACE = SCRIPT_DIR / "csv_workspace"   # 受 allowed_write_paths 约束的工作区，每次新建、退出清理
WORKSPACE.mkdir(parents=True, exist_ok=True)
TARGET = WORKSPACE / "top_cities.csv"

TASK = f"""Go to https://en.wikipedia.org/wiki/List_of_largest_cities and collect the top 10 cities by population.
Then use the write_file tool to save a CSV (columns: rank,city,population) to: {TARGET}
After saving, read the file back with read_file to verify it looks correct, then tell me the file path.""".strip()


async def main() -> None:
	logging.basicConfig(level=logging.INFO)
	settings = load_settings()
	if not settings.llm.api_key:
		print("Error: 请设置 ZHIPU_API_KEY 环境变量")
		sys.exit(1)
	if not settings.browser.ws_url:
		print("Error: 请先用 chrome --remote-debugging-port=9222 启动 Chrome")
		sys.exit(1)

	# write_file/replace_file 受 allowed_write_paths 白名单约束（前缀匹配）
	agent_settings = replace(settings.agent, allowed_write_paths=[str(WORKSPACE)])
	llm = LLMClient(settings.llm)
	browser = BrowserSession(settings.browser)
	agent = Agent(task=TASK, llm=llm, browser=browser, settings=agent_settings)
	history = await agent.run()

	print("done:", history.is_done())
	if TARGET.exists():
		print(f"\n--- {TARGET} ---")
		print(TARGET.read_text(encoding="utf-8")[:1000])

	input(f"\n按 Enter 清理工作区 {WORKSPACE} ...")
	shutil.rmtree(WORKSPACE)


if __name__ == "__main__":
	asyncio.run(main())
```

**适配注意点 / 验证点**：
- `allowed_write_paths=[工作区]` 是必须的（白名单前缀匹配），否则 `write_file` 会被拒。仿 `examples/file_system/file_system.py`。
- 运行结束会 `input()` 等你确认后清理 `csv_workspace/`；想保留文件可注释掉 `shutil.rmtree`。
- Wikipedia 页面结构可能变动；若 agent 抓不到，可在 TASK 里换更简单的数据源或直接让它"编造 10 个示例城市"以验证 CSV 生成流程（仅 demo 用途）。

- `csv_generation.py`：`examples/features/csv_workspace/top_cities.csv` 生成且内容为合法 CSV。

## 风险 / caveat

- 下载落地路径由 Chrome 决定，TreeWalker 无法指定/重定向——这是能力差异，非 bug。
- CSV 示例依赖目标页结构；验证重点是"write_file 写 CSV + 白名单"流程跑通，而非数据绝对准确。
- 本 issue 不涉及 `src/` 改动。
