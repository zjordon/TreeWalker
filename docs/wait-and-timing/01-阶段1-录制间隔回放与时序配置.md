## Context（为什么做）

重放（replay）目前几乎全靠固定 `asyncio.sleep(delay)` 等待（`agent/rerun.py:437`）。三个具体短板：

1. **用户录制的真实操作节奏被丢弃**：录制后端给每个 `ActionRecord` 记了 `timestamp`（来自扩展 `Date.now()`），但 `recorder/flatten.py` 落盘成 `AgentHistoryList` 时没填 `step_interval`，导致用户录制回放全部走固定兜底延迟，与用户真实操作节奏脱节。
2. **时序参数不可配置**：`delay_between_actions` / `max_step_interval` / `wait_for_elements` 既是 `rerun_history()` 的 kwargs，又被 CLI / TUI 硬编码成 `1` / `5`，用户无法通过 settings / env 调整。
3. **已有的智能等待不用于重放**：`_wait_for_page_settle`（轮询 `document.readyState` 到 `complete`）只在 agent 主循环路径用，重放 `_execute_history_step` 的 `get_state()` 前是裸调用，未等页面稳定。

本阶段目标：用最小改动补齐这三点，且**对现有重放零行为变更**（默认值对齐现状、新开关默认关）。

## 现状精确锚点（已核验真实代码）

### 缺口 3：flatten 丢 timestamp `flatten.py:29-54`

`ActionRecord.timestamp` 是 `float`、单位**秒**（`translation.py:_ts_seconds` 把扩展毫秒 `/1000`）。`flatten` 把每个 action 转成一步 `AgentHistory`，但 `StepMetadata` 只填了 `start==end==timestamp`，没传 `step_interval`：

```python
# recorder/flatten.py:29-54（现状）
def _action_to_history(action: ActionRecord, step_number: int) -> AgentHistory:
    ...
    return AgentHistory(
        ...
        metadata=StepMetadata(
            step_start_time=action.timestamp,
            step_end_time=action.timestamp,   # ← start==end → duration_seconds 恒 0
            step_number=step_number,
            # ← 没传 step_interval，默认 None
        ),
    )
```

后果：重放端 `_compute_step_delay`（`rerun.py:338-344`）拿到 `metadata.step_interval` 恒为 `None`，全部走 `delay_between_actions` 兜底。

> ⚠️ **不能照搬 agent 自录路径**：`step.py:1109` 用 `step_interval = prev.metadata.duration_seconds`，但 flatten 里每步 `duration_seconds` 恒 0，照搬会得到恒 0 的间隔。必须用**相邻 action 的 timestamp 差**。

### 缺口 4：时序参数硬编码

`AgentSettings`（`config.py:73-120`，纯 `@dataclass`、非 pydantic）没有任何 rerun 时序字段；`Agent.__init__`（`agent.py:58-79`）不保留 `self.settings` 聚合，而是逐字段拆到 `self.xxx`（`rerun_history_dir` 是现成范本，`agent.py:78`）。

`rerun_history` 签名默认值是 2.0/45.0，但 CLI / TUI 都显式覆盖成 1/5：


## 方案

### 缺口 3：flatten 填 step_interval

给 `_action_to_history` 加 `prev_ts: float | None` 参数，用相邻 action 的 timestamp 差作为 `step_interval`。

```python
# recorder/flatten.py（改后）
def flatten(recording: Recording) -> AgentHistoryList:
    """``Recording`` → ``AgentHistoryList``（step_number 重排 0..N-1）。"""
    steps = [
        _action_to_history(
            action,
            step_number=i,
            prev_ts=recording.actions[i - 1].timestamp if i > 0 else None,
        )
        for i, action in enumerate(recording.actions)
    ]
    return AgentHistoryList(history=steps)


def _action_to_history(
    action: ActionRecord, step_number: int, prev_ts: float | None
) -> AgentHistory:
    ...
    # 录制回放专用：step_interval = 相邻 action 的 timestamp 差（人类操作间隔近似）。
    # 不能用 prev.metadata.duration_seconds——flatten 里 start==end==timestamp，恒 0。
    # timestamp 已是秒（translation._ts_seconds /1000），减法直接得秒。
    step_interval = action.timestamp - prev_ts if prev_ts is not None else None
    return AgentHistory(
        ...
        metadata=StepMetadata(
            step_start_time=action.timestamp,
            step_end_time=action.timestamp,
            step_number=step_number,
            step_interval=step_interval,
        ),
    )
```

**首步**（`i==0`）：`prev_ts=None` → `step_interval=None`，与 agent 自录首步语义一致（`step.py:1109`）。重放端 `_compute_step_delay` 对 `None` 走 `delay_between_actions` 兜底，对非 `None` 走 `min(step_interval, max_step_interval)` 封顶——用户发呆 60s 不会真等 60s。

### 缺口 4：时序参数可配置

**4.1 新增 `AgentSettings` 四字段**（`config.py`，紧跟 `rerun_history_dir` L113 之后）：

```python
# config.py（改后，新增四字段）
rerun_history_dir: str = "rerun-history"
# ── 重放时序（阶段 1）：默认值对齐 CLI/TUI 现状硬编码，避免改变现有行为 ──
rerun_delay_between_actions: float = 1.0     # 步间兜底延迟（秒）；对齐原 CLI/TUI 的 1
rerun_max_step_interval: float = 5.0         # step_interval 封顶（秒）；对齐原 CLI/TUI 的 5
rerun_wait_for_elements: bool = False        # 等元素数量（既有粗粒度等待）；对齐 rerun_history 默认
rerun_wait_for_page_settle: bool = False     # get_state 前等 readyState（缺口 1）；默认关=零行为变更
```

> ⚠️ 默认值**必须**取 1.0/5.0（CLI/TUI 现状），**不能**取 `rerun_history` 自身的 2.0/45.0——否则会把重放从 1/5 变成 2/45，显著变慢。

**4.5 `rerun_history` 签名改 None 哨兵 + 归一化**（`rerun.py:253-264`）：

```python
# rerun.py（改后签名）
async def rerun_history(
    self,
    history: AgentHistoryList,
    *,
    max_retries: int = 3,
    skip_failures: bool = False,
    delay_between_actions: float | None = None,      # ← None 哨兵

    wait_for_elements: bool | None = None,           # ← None 哨兵

    summary_llm: LLMClient | None = None,
    ai_step_llm: LLMClient | None = None,

    if max_step_interval is None:
```

### 缺口 1：page-settle 复用（仿 screenshot 范式）

给 `BrowserSession.get_state(...)` 加 `wait_settle: bool = False` 形参，内部在现有逻辑前调 `_wait_for_page_settle()`（`try/except + warning`，与 screenshot 一致）。

```python
# browser/session.py:1528（改后签名）
async def get_state(
    self, include_screenshot: bool = True, wait_settle: bool = False
) -> BrowserStateSummary:
    """Get full browser state: URL, title, tabs, DOM, optional screenshot.

    wait_settle: poll document.readyState to 'complete' before reading state
    (mirrors screenshot/save_as_pdf). 失败只打 warning，不阻断 get_state。
    """
    if wait_settle:
        try:
            await self._wait_for_page_settle()
        except Exception as e:
            logger.warning("Pre-get_state wait_settle failed: %s", e)
    sid = self.current_session_id
    ...  # 原逻辑不变
```

```python
# agent/rerun.py:437-438（改后，注入点）
await asyncio.sleep(delay)
state = await self.browser.get_state(
    include_screenshot=False, wait_settle=wait_for_page_settle
)
```

> 不选的另一条：rerun 直接 `await self.browser._wait_for_page_settle()`——能跑，但 `_wait_for_page_settle` 是单下划线私有方法，跨类直接调破坏封装约定，且需自己加 `try/except`。`get_state` 形参方案与 screenshot/save_as_pdf 既有 precedent 一致，故推荐。

## 关键决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 默认值取 **1.0/5.0**（非 `rerun_history` 的 2.0/45.0） | 对齐 CLI/TUI 现状，避免重放变慢；阶段 1 零行为变更 |
| 2 | `rerun_history` kwargs 用 **None 哨兵** | 方法默认值不能引用 `self`；`None` 让显式传值（含测试 `=0`）优先，省略即读 settings |
| 3 | `wait_settle` 走 **`get_state` 形参** | 复用 screenshot/save_as_pdf 既有范式，不破坏 `_wait_for_page_settle` 的私有封装 |
| 4 | `step_interval` 用 **相邻 timestamp 差**（非 `duration_seconds`） | flatten 里 `start==end==timestamp`，`duration_seconds` 恒 0 |
| 5 | 所有新开关 **默认关** | 阶段 1 对现有重放零行为变更；用户按需 `AGENT_RERUN_WAIT_FOR_PAGE_SETTLE=true` 开启 |

## 边界与风险

| 项 | 说明 |
|---|---|
| **SPA 局限** | `readyState` 在 SPA 常年 `complete`（SPA 导航不改 readyState），缺口 1 对 SPA 导航收益小，主要帮传统整页跳转。SPA 时序问题靠阶段 2（等目标元素）/ 阶段 3（networkidle）。 |
| **`step_interval` 语义迁移** | 录制回放路径下其含义从"上一步 LLM+动作耗时"变为"上一步到当前步的人类操作间隔"。两者在重放端都经 `_compute_step_delay` 的 `max_step_interval` 封顶，行为一致；完整语义澄清（与 agent 自录路径统一）留给阶段 4（缺口 7）。 |
| **None 哨兵兼容性** | 现有测试均显式传非 None 值（`=0`），None 哨兵不影响；仅需确认 `rerun_history` 的所有调用点（CLI/TUI/examples/tests）行为不变。 |
| **`get_state` 签名扩展** | 新增 `wait_settle` 形参有默认值，所有现有 `get_state(...)` 调用点不受影响。 |
