## 一、形态分类（5 类，附真实工具）

| # | 形态 | 代表工具（已查证） |
|---|---|---|
| 1 | **浏览器扩展 popup / 独立窗口 / side panel** | Selenium IDE（独立窗口）；早期 Selenium IDE Firefox 版曾是侧栏 |
| 2 | **浏览器 DevTools 面板** | Chrome DevTools Recorder（⋮ → More tools → Recorder） |
| 3 | **独立桌面应用** | UiPath Studio（Windows, WF4/.NET）；Cypress Studio / Test Runner（Electron）；mabl Trainer（桌面客户端）；BrowserStack Low-Code（桌面应用） |
| 4 | **Web 应用 / 本地 HTTP 服务 + 浏览器** | testRigor、Reflect.run（云端 SaaS，纯浏览器编辑）；**Playwright Trace Viewer**（本地 `npx playwright show-trace` 起的 localhost PWA，只读） |
| 5 | **IDE 扩展（VSCode 等）** | **最薄的一类**——多数 IDE 扩展只跑/调试测试，不做"录完的步骤列表"可视化编辑。Playwright VS Code 扩展把 Codegen/Inspector 拉进 VS Code，但生成物仍是**代码文件**，编辑发生在代码编辑器里。Cypress Studio 原版的"Studio code panel"也只是嵌入 IDE 的文本框。**未发现**有 IDE 扩展提供表格/卡片式步骤编辑器。 |

**形态 4 内部细分**（影响 TreeWalker 选型）：
- 4a. 云端 SaaS（testRigor/Reflect/mabl/BrowserStack）：测试存服务器、登录、云回放——**不适合本地 JSON 场景**
- 4b. **本地 HTTP 服务 + 浏览器**（Playwright Trace Viewer）：本地起服务、本地文件、浏览器打开——**与 TreeWalker「本地 JSON + Python 后端」高度同构**

## 二、重点工具编辑交互细节（逐个查证）

### 2.1 Selenium IDE —— 三列表 + 表下输入框

- **形态**：Chrome/Firefox/Edge 扩展，点图标后**开自己的独立窗口**（不是 popup、不是 side panel）。
- **动作列表**：中央 Editor 面板是一张**三列表**：`Command` / `Target` / `Value`（底层 `.side` JSON 还含 `id/comment/targets`）。还有 Table/Source 两个 tab，Source 直接看底层 HTML/JSON。
- **改参数**：**不是双击 inline**。点选某行 → 表格**下方**的 `Command / Target / Value` 输入框被填充，在那里改。Command 字段带自动补全下拉；Target 旁有 "Select target in page"（去页面点选元素抓定位）和 "Find"（高亮校验）。**双击一行是"单独执行该步"**，不是编辑。
- **变量**：纯文本语法 `${varName}`，没有专门建变量 UI。配合 `store` 命令族：`store / store text / store value / store attribute / store title / store json / store xpath count`。CSV 数据驱动**不原生支持**，靠命令行 runner + `csv2json` 预处理 + `for each` 循环拼。
- **删/插/重排**：右键 → "Insert new command"（在当前行上方插空白行）；**拖拽重排**（FAQ 明确提到 drag-and-drop）；删除走右键菜单 / Edit 菜单。
- **其他**：控制流命令（`if/else/end`、`while/end`、`times/end`、`do/repeat if`、`forEach/end`）；断点（点行首左边栏）；base URL 字段；测试/套件侧栏；**代码导出 6 种**（Java JUnit / C# NUnit / C# xUnit / JS Mocha / **Python pytest** / Ruby RSpec）；CLI runner `selenium-side-runner`。

### 2.2 Chrome DevTools Recorder —— 可展开的步骤卡片列表

- **形态**：DevTools 面板，路径 `⋮ → More tools → Recorder` 或命令菜单搜 "Recorder"。Chrome 97+ 引入，至今文档仍标 "preview feature"。**未弃用**——2025 年的 "Recorder 弃用" 传言其实是另两个功能（Performance Insights 面板 Chr137 移除、JS live-edit Chr145 移除）。
- **动作列表**：**纵向可展开的步骤卡片列表**；每张卡默认显示摘要（步骤类型 + selector 预览），点 **Expand 按钮**展开露出可编辑字段。
- **改参数**：展开后 inline 改字段；**可改 `type`**（点 `type` 旁的值出下拉，把 click 改成 hover）；**selector 是数组**（一组备选），可逐条加/删；有 "Select" 按钮去页面拾取；录制开始时可选 "Selector attribute"（如 `data-testid`）影响生成倾向。
- **变量**：**原生不支持**变量/参数化/数据驱动循环。要变量得手改导出的 JSON，或写 stringify 扩展插件。
- **删/插/重排**：三点菜单/右键 → "Remove step" / "Add step before" / "Add step after"；**复制为** JSON / Puppeteer / @puppeteer/replay；**拖拽重排官方文档未提及**（视为不支持）。
- **其他**：**断点**（hover 步骤旁圆圈切换）；**断言**（"Add assertion" 生成 `waitForElement` 步骤，支持 `>= / == / <=` 比较、count、visible、attributes、properties）；**导出** JSON / @puppeteer/replay / Puppeteer / Puppeteer+Lighthouse，扩展插件可加 Cypress / Nightwatch / WebdriverIO / Testing Library；**导入** JSON；**扩展 API** `chrome.devtools.recorder`（Chr105+ `registerRecorderExtensionPlugin` 加导出格式，Chr112+ `createView` 嵌自定义回放视图）。

### 2.3 UiPath Studio —— 画布 + Properties 面板（重型 IDE）

- **形态**：Windows 桌面应用，基于 **Windows Workflow Foundation (WF4) / .NET Framework**（"WPF" 官方未明说，但 WF4 设计器惯例是 WPF）。三个产品线：Studio（专业）/ Studio for Citizen Developers（旧名 StudioX，2025-07 改名）/ Studio Web（浏览器版）。
- **动作列表**：录制产物落在 **Designer 画布**上的一个 `Use Application/Browser` 容器内，含 `Click / Type Into / Select Item / Check / Keyboard Shortcuts` 等活动。
- **改参数**：**两条路并存**——(a) 画布上活动卡片 inline 改（需开 "Show activity properties inline" 设计设置；Compact Mode 把主属性塞进活动标题，`Ctrl+Shift+E` 开 Expression Editor）；(b) 右侧 **Properties 面板**按 `Common / Input / Options / Output / Misc / Target` 分类表单编辑。Click 活动的 Input 类含 `ClickType / MouseButton / Target.Selector / Target.Timeout / Target.WaitForReady(None/Interactive/Complete)`；Type Into 含 `Text / Empty field / Delay between keys / Click before typing / Input mode(Same as App/Browser, Hardware Events, Simulate, Chromium API, Windows Messages)`。
- **变量**：Data Manager 面板里的 **Variables 子面板**（列：`Name / Variable Type / Scope / Default`），类型可选 Boolean/Int32/String/Object/DataTable/Array<T>/Browse；**inline 快捷键 `Ctrl+K`** 在输入框里直接建同类型变量；**`Ctrl+M` 建 In 参数，`Ctrl+Shift+M` 建 Out 参数**。
- **删/插/重排**：`Delete` 键删；**画布拖拽**或 cut-paste 重排；Sequence / Flowchart（Flow Decision/Switch）/ State Machine 三种容器分组；`Ctrl+D` Comment Out、`Ctrl+E` 启用、`Ctrl+T` Surround with Try Catch、**Extract as Workflow**（抽成新 workflow + 自动建参数）、Auto Arrange。
- **其他**：**UI Explorer**（Visual Tree + Selector Editor + Selector Attributes + Property Explorer 四面板，按钮：Indicate Element / Indicate Anchor / Repair / Highlight）；左侧 Activities 库（搜索/拖拽/双击添加）；断点 `F9`（含条件和命中次数）；书签 `Ctrl+Shift+M`、标注 `Shift+F2`、Markers 面板 `Ctrl+Shift+B`；Locals 面板（调试时看运行时值）。

### 2.4 testRigor —— 纯 Web 应用，"一行一句英语"

- **形态**：纯云端 SaaS（`app.testrigor.com`），无桌面客户端、无本地版、登录才能用。
- **动作列表**：**就是一段文本**，每行一句英语（不是表格/卡片）：
  ```
  login
  click on "My Profile"
  enter "1403, Ashley Street" into "Address"
  click on "Save"
  check that page contains "Profile Saved"
  ```
  底层 YAML 里是 `customSteps: |` 块、newline 分隔。
- **改参数**：**改那行文本**。元素定位用 AI/NLP（`click "cart icon" using AI`、`using OCR`），**没有"改 selector"概念**——靠可见文字/标签；支持 `click button "Search"`、`click on the 3rd "hello"`、`click on exactly "Delete"`（大小写敏感）。
- **变量**：三套并存——(a) Test Data 区建全局变量（text/multi-line/hidden/file），用 `stored value "firstName"` 解引用；(b) **`${var}` inline 插值**（含预定义 `username/password/currentUrl/todayYear/nowHour` 等）；(c) **CSV Data Sets**（上传 CSV，列名为变量名，每行跑一次）。
- **删/插/重排**：**就是改文本**——加/删/移行。官方公开文档**未提及**专门的拖拽手柄或右键菜单 UI（未查证）。
- **其他**：Reusable Rules（命名子程序，可带参，支持 `Save, then Find and Replace Steps`）；Chrome 扩展可录英语；导出 Selenium/Playwright **未查证**（产品定位是 codeless 替代品）。

### 2.5 Reflect.run（SmartBear）—— 纯 Web 应用，"可编辑的步骤描述 + 重录"

- **形态**：纯云端 SaaS（`app.reflect.run`），云端浏览器录制，服务器存测试。
- **动作列表**：录制后每步**自动生成一句可编辑的描述**（如 `"Click on the 'Login' button"`），用户可"enhance and enrich"。管理视图是测试**表格**（Test name/运行时间/步数/时间戳），编辑器官方称 "interactive test editor"，"real-time 更新"——但内嵌的步列表具体长什么样**未查证**（在登录墙后）。
- **改参数**：步级编辑支持"自然语言 prompt 加步"、失败时"delete and retry steps"、"validate outcomes"；**Edit & Rewind** 可回放到某步重录；元素选择默认抓"多组多样 selector"做缓存，过期时 AI+视觉兜底。
- **变量**：Variables & Assertions 支持；**Segments = 可复用、可带参的步骤组**（SmartBear MCP schema 明确 "reusable test steps with an optional set of parameters"）。
- **删/插/重排**：**重录优先于精细改参**（"one-click re-record" / "Edit & Rewind"），未查证拖拽 UI。
- **导出代码**：**未发现**——定位是 no-code，浏览器即编辑器。

### 2.6 mabl —— 云平台 + 桌面 Trainer（混合形态）

- **形态**：云平台，但**编辑器是桌面客户端 Trainer**，从网页"Edit with mabl"启动。
- **动作列表**：**带序号的步骤列表**，每步是 **AI 生成的意图描述**（例：把"Insert the value of 'app.defaults.username'..."自动改写成"Enter the user's email address."）。
- **改参数**：hover 步骤 → **铅笔图标**编辑（改完 AI 重新生成描述）；hover → **…(More actions)**；**双击步名重命名**（手改名永不被 AI 覆盖）；More Actions → Annotate 加备注；**Configure Find** / Custom find steps（CSS/XPath）改定位；Wait steps + Intelligent Wait；**hover 步骤号出复选框 → 顶部批量菜单**（Copy / Disable-Enable / Create flow / Delete / 改断言失败行为），Shift+click 连选。
- **变量**：Trainer 窗口有 **Variables 按钮**；带条件/数据库/JS snippet/MFA/Flow/Loop/Echo/API/Step group 等 + 步插入菜单。
- **删/插/重排**：**click-and-drag 重排**；插入 = 把 "Waiting for input" 游标拖到目标位置 → 录或点 **+** 菜单加步；`Ctrl+F` 搜步骤；顶部 Undo/Redo。
- **自愈**（这一档里文档最全）：每步每环境维护 element history（属性/祖先/custom test ID），失败先找强匹配，否则 Standard auto-heal（部分匹配），云端再失败用 **Advanced auto-heal（生成式 AI 找语义相似）**；每步 Find summary 带 confidence，低置信直接失败而非误改；可 Configure Find 关单步自愈。
- **导出**：CLI `mabl tests export {id} --format side|playwright`（也有 json/csv/yaml）；**部分步类型不导出**（拖拽、JS、API、cookie、文件上传、下载断言、accessibility、MFA 等）。

### 2.7 BrowserStack Low-Code —— Web + 桌面双形态

- **形态**：官方明说"offers both a web-based application and a desktop application"。
- **动作列表**：录制器面板里的**步骤列表**，点开任一步进 "step details" 视图。
- **改参数**：**两条路**——(a) 不开录制器就能改 wait timeout / URL / 自定义 locator / **重排步骤** / 步骤转 module，改完 Save；(b) 开录制器（三点 → Edit with recorder）可"在已有步骤中间录新步"、更新截图、删步。**关键技巧**：要插步前，要么手动暂停录制器、要么用 **"Execute till here"** 按钮自动跑到目标页。
- **变量**：把输入文本"Convert into Variables"复用；Functions 填动态值；Custom JavaScript 兜底（具体 sigil 语法**未查证**）。
- **删/插/重排**：**hover 步骤出 6 点拖拽手柄**重排；约束：第一段 Open URL 不能动、一次只能移一步、移完不能破坏"变量先定义后使用"、改顺序会生成新 test version。
- **其他**：步转 modules（可复用组）；自愈宣称"智能处理元素属性变化"（比 mabl 粒度粗，无置信度模型）；导出 Selenium/Playwright **未在 LCA 文档发现**。

### 2.8 Playwright Trace Viewer（参考：本地 PWA 的只读标杆）

- **形态**：本地 web app。`npx playwright show-trace trace.zip` 起一个 localhost PWA；也有静态版 `trace.playwright.dev`（拖入 zip，全在浏览器里处理，不上传）。
- **展示**：左侧图标栏切"透视"（Actions/Screenshots/Snapshots/Source/Call/Log/Errors/Console/Network/Metadata/Attachments），底部 Timeline 滑块。Actions 是带 locator 和执行时间的列表；主视口是 Before/Action/After DOM 快照并高亮目标节点；Call tab 给每步元数据（类型/locator/时长/strict 模式/按键）。
- **编辑**：**完全只读**，文档通篇"explore/replay/navigate"措辞，**没有任何编辑或导出代码**。
- **关系**：Playwright 故意把生命周期切成三件 disjoint 的工具——**Codegen**（录 → 实时生成代码到 Inspector 窗口，Copy 出来，UI 内无序列编辑器）、**Inspector**（断点调试器，带 Pick Locator 字段可现场改单个 locator，但不存动作）、**Trace Viewer**（事后只读回放）。**编辑永远推给你的 IDE。**

### 2.9 Cypress Studio（警示案例）

- **形态**：Cypress 桌面 App/Test Runner 内嵌（Electron）。
- **历史**：6.3.0 引入（experimental）→ **10.0 移除**（2022-05-18 blog：重构成本高于价值，把用户导向 Chrome Recorder）→ **10.7 又加回**（experimental）→ **15.4.0 转 default** → **15.11.0 加 "Studio AI" 层**。
- **编辑**：入口按钮 New Test / Edit in Studio（Command Log 上）→ Studio 跑到末步、进录制模式，**只支持 append**（官方原话"New recorded actions and assertions are always appended to the end of your test"）；当前版本有"Studio code panel"是个**文本编辑器**（"edit any portion of the test code directly"），Undo/Redo/Reset；Save 写回 `.spec.js`。
- **变量**：**不支持**；录制产物是字面量 `.click()/.type()` 行；数据驱动要手改 spec。
- **删/重排**：当前版本靠 Undo/Redo/Reset + 改文本；老 6.3 版无文档化的逐步 UI。
- **教训**：Cypress 两次试紧密耦合的 in-app 编辑器，第一次因重构成本被砍，第二次靠 AI 才维持——**做一个"录完的测试编辑器能自负盈亏"很难**。

## 四、对 TreeWalker 的 3 个候选推荐

### 关键约束（决定选型）
1. 录制扩展要迁去 TreeForge——**编辑器不能强依赖"录制扩展留在本仓库"**（除非编辑器是独立扩展/独立服务）。
2. 编辑对象是 TreeWalker 的 `AgentHistoryList`（`rerun-history/*.json`，本地文件）。
3. 已有 aiohttp 后端（8765）和 MV3 扩展（WXT+React）两套现成件。
4. **变量当前不持久化**——`detect_variables()` 是运行时规则检测，`load_and_rerun(variables=...)` 是运行时替换。"标值为变量"的 UI 需要引入一种持久化形式（JSON 内标注，或 sidecar 文件）。

### 推荐排序：A > C > B

#### ★ 推荐 A（首选，已选）：本地 HTTP 服务 + 浏览器 SPA（仿 Playwright Trace Viewer 模式，加编辑能力）

**形态 4b**。aiohttp 加几个端点 + 托管一个静态 SPA，用户浏览器开 `http://127.0.0.1:8765/editor` 编辑。

- **复用 TreeWalker 现成件**：
  - **aiohttp 后端**：加 `/history/list` `/history/load?name=xxx` `/history/save?name=xxx`（带 `resolve_rerun_path` 同款相对路径校验，复用 `AgentHistoryList.load_from_file` / `save_to_file`）。
  - **`AgentHistoryList` 模型 + `registry_version` 校验**：加载/保存直接复用，编辑器产物天然兼容 `load_and_rerun`。
  - **`detect_variables()`**：编辑器调用后端拿"建议变量"，UI 上勾选确认 → 写回 JSON 的一个新字段，`load_and_rerun` 同步读它。
  - **前端**：复用扩展的 React 经验；选 React + Vite 单页构建，产物由 aiohttp `web.static` 托管。
- **工作量**：**中**。前端是大头（表格/侧栏表单/拖拽/变量标注），后端只是 CRUD 端点。MVP（只读列表 + 改参数 + 删步）约 1-2 周；完整（变量标注、合并步、断点）3-5 周。
- **优劣**：
  - ✅ **完全独立于录制扩展**（录制扩展迁走毫无影响）。
  - ✅ 与"本地 JSON + Python 后端"同构，**和 Trace Viewer 一个模子**，用户好理解。
  - ✅ 任意浏览器、离线、无扩展更新摩擦。
  - ✅ 后续扩展性强（加重放按钮 → 直接调 `load_and_rerun`；加截图 → 嵌入 `screenshot_path`）。
  - ❌ 需要前端构建流水线（但 WXT 那套已经在仓库里，照搬即可）。
  - ❌ aiohttp 静态托管要注意 SPA 路由 fallback。

#### 推荐 C（保底 / 渐进）：单文件静态 HTML 编辑器（File System Access API）

一个 `tools/history_editor.html`（vanilla JS 或 Preact 单文件），双击打开 → 文件选择器选 JSON → 表格编辑 → 保存（Chrome/Edge 用 File System Access API 直接写回磁盘；Firefox/Safari 走下载）。

- **复用**：直接读 `AgentHistoryList` JSON schema；变量逻辑可在前端重实现一份，或先不做、纯手工标 `${var}`。**不需要后端改动**。
- **工作量**：**小**。MVP 1-2 周内可出。
- **优劣**：
  - ✅ **零后端改动、零扩展、零构建**；最容易落地。
  - ✅ 完全离线；可 commit 进仓库当工具用。
  - ✅ 独立于录制扩展。
  - ❌ File System Access API 保存**仅 Chrome/Edge**；Firefox/Safari 只能下载再替换。
  - ❌ 没后端 = 无法调 `detect_variables` / `registry_version` 校验 / `load_and_rerun` 试跑——要么前端重实现，要么放弃这些能力。
  - ❌ 难演进到推荐 A 的完整体验（最终还是要重写）。

#### 推荐 B（次选）：一个独立的"编辑器扩展"（side panel），与录制扩展解耦

**形态 1**。新建一个 entrypoint 或独立扩展，用 **chrome.sidePanel API**（Chrome 114+）做常驻侧栏编辑器。**只做编辑、不做录制**，所以录制扩展迁去 TreeForge 不影响它。

- **复用**：WXT + React 工具链照搬；通过 `fetch('http://127.0.0.1:8765/history/...')` 调推荐 A 那套端点（**A 和 B 共享后端端点**）。
- **工作量**：**中**。和 A 差不多，但多了扩展打包/签名/更新的维护负担。
- **优劣**：
  - ✅ Chrome 原生常驻侧栏，**和被编辑页面同屏**（如果将来要做"点步定位元素"很有用）。
  - ✅ 复用 WXT/React 经验。
  - ❌ **Chrome-only**（sidePanel 是 Chromium 114+ 独有；Firefox sidebar API 形态不同；Safari 无）。
  - ❌ 要装扩展、要更新；多一个二进制产物。
  - ❌ 与推荐 A 后端端点重复，**A 是 B 的超集**——所以 B 的边际价值在于"原生侧栏 UX"，但要付跨浏览器兼容代价。

### 决策建议
- **若想要最终形态最好且能投入 3-5 周**：直接做 **A**。它与 Trace Viewer 同构、与 TreeWalker 后端同构、独立于 TreeForge 迁移，长期可演进。
- **若想先快速验证"可视化编辑到底要不要做"**：先做 **C**（1-2 周），用户用得起来再升级到 A。C 是 A 的可抛弃探路。
- **不推荐 B 单独做**：它的后端和 A 完全一样，前端又要受 Chrome-only sidePanel 限制——除非已决定"编辑器必须和被编辑页面同屏"，否则 A 用一个浏览器 tab 已经够用。

### 一条横向建议（不管选哪个）
变量持久化方案要先定：在 `AgentHistoryList` 加一个顶层 `variables`（或 `manual_variables`）字段，登记"变量名↔原值/位置"。`load_and_rerun` 同步读这个字段、`detect_variables` 改成"检测建议 + 读已存变量"两段。这一步是 A/B/C 都要做的、独立于形态的工作。
