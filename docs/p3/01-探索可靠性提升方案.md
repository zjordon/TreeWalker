> 状态：方案（待 P0 落地）

> 承接：[[browser-wait-and-timing]]（actionability 理论）、[[state-aware-runtime]]（候选/已提交）、[[browser-automation-knowledge-map]]（L3/L3.5 层）；重放端已落地 actionability（rerun.py）。

## Context（为什么做）

战略转折后主线是「提升 agent 自动探索成功率」。但探索端 `step.py:_execute_actions` 今天**盲发动作**——点击/输入前零 visible/stable/enabled 检查、零 page-settle/networkidle 等待。重放端（rerun.py）已落地完整 actionability（[[browser-wait-and-timing]] 的 Playwright 五级检查 + 乐观重试/悲观超时），却 replay-only。

后果：元素还没渲染好/还在动画/被遮挡就点 → 假失败 → consecutive_failures 累加 → 提前停；或点错元素 → 状态不同步（[[state-aware-runtime]]「错误级联」）。

本方案把重放端已验证的 actionability 移植到探索端（P0，最高价值、复用现成代码、纯增量），并给出失败恢复 / 多跑选优 / 产物质量评估的设计方向（P1-P3）。

## 关键设计决策

⚠️ **核心纠正**：rerun 的 `_wait_for_actionability` 用 `_locate_target(hist_elem)` 重定位（匹配录制指纹）；探索侧无 hist_elem，LLM 直接给 live `index` → 探索变体内层改 `selector_map[index]` 重定位，其余 deadline+poll+降级骨架原样复用。纯函数 `_is_actionable`/`_is_file_input`/白名单**零改动**直接复用。

**默认开**（用户决策）：探索 actionability 默认 ON（异于重放端默认 OFF）——探索可靠性即 P2 目的。降级原则不变（超时/拿不到 node → 照常执行，永不引入新失败），故对 mock/空 selector_map 的单测零影响。

**纯增量、只"等"不"挡"**：P0 只做"等"（给慢渲染元素时间变 actionable），不做"挡"（不跳过/不报错）。挡动作归 P1。

**抽共享模块** `agent/actionability.py`（单一事实源，对齐 dom-snapshot 抽取原则）：迁 rerun.py 的 3 纯函数 + 白名单过去，rerun.py 改 import；新增探索侧 `wait_for_actionability`（index-based）+ `is_rect_stable`（browser 参数）。

## 风险与回退
- **默认开改变现有测试行为**：靠"node 拿不到→跳过 wait"+ `is_actionable` 对 None 字段保守放过，保证 mock/空 state 零影响；全量回归把关。
- **延迟**：每个白名单动作最多多等 timeout（默认 1.5s）；succeed-fast（立即可操作即返）。可 env 调小/关。
- **index 漂移**：wait 中 refresh 后 index 可能变 → `selector_map.get(index)` 拿不到 → 降级照常执行（=今天行为）。
- **回退**：`AGENT_EXPLORATION_ACTIONABILITY_CHECK=false` 即恢复盲发；或 revert step.py 插入块。

## P1-P3 分级设计（本期暂缓，仅方向）

### P1 探索失败恢复（候选/已提交状态机，[[state-aware-runtime]]）
- 每个动作建模为 候选→验证→提交/拒绝：actionability + post-action drift 作验证门；通过才 commit（append history），否则有界 retry/回退。
- wire loop_detector（今天只软 nudge）+ consecutive_failures 进恢复决策：retry 单动作 / replan / 放弃。
- 修 consecutive_failures 不计多动作失败的语义（step.py:987-994）。
- 风险：retry 引入新失败模式 → 严格有界 + 降级。

### P2 多跑选最优
- 新编排 `explore_multi(task, n=3)`：跑 N 次 `agent.run()`，打分选最优存历史（依赖 P3 打分）。每次 run 隔离；代价 N× LLM。新 `agent/exploration_runner.py` 或 agent.py 方法。
- 判据：成功率/步数/judge verdict 综合排序。

### P3 产物质量评估
- `score_history(history) -> RunQuality`：success（is_successful）+ step 数 + error 数 + judge verdict + loop/stagnation（**需把 loop_detector 统计持久化进 StepMetadata/AgentHistory**，今天仅 agent 实例内，agent.py:104）+ plan churn。
- 新增 StepMetadata 字段持久化 loop/stagnation；服务 P2 选优 + 离线 trace 评估（[[state-aware-runtime]] Trace-Native Evaluation）。
