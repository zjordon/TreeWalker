## 2. 重开的合法内核：主导形态无修复候选

#185 修复复活的自愈只覆盖两类候选（裸 return 包 IIFE / 缺 catch 补 catch）；C 轮 **18/22 的缺/多闭合形态没有候选**——因为方案 §8 明确把「定界符平衡修复候选」**后置不做（"先观测"）**。C 轮就是那个观测：

- 缺闭合（13 处）：`((function(){ BODY })()` —— 栈计数得 `(` 未闭合 → 候选=补 `)`（或重建 `)})()` 尾部）
- 多余闭合（5 处）：`...return 'not found'}})())` —— 尾部多余 `}`/`)` → 候选=剥除尾部多余闭合符再重验平衡
- 语法错误无副作用，候选按序试跑的设计哲学（session.py 既有）原样适用——**解除后置，本轮实施**

## 3. 修复方案（P0 三项）

1. **平衡修复候选**（`_syntax_repair_candidates` 扩展）：字符串/模板字面量感知的栈计数——
   - `Unexpected end of input`：补缺失闭合符（按栈序逆置；`((` 前缀配 `})()` 调用括号重建），生成 ≤2 个候选按序试跑；
   - `Unexpected token '}'`/`')'`：剥尾部多余闭合符至平衡（≤2 候选）；
   - 与既有候选共用试跑通道（编译期错误、无副作用、全部失败抛原错）。
2. **截断提示措辞修正**：`"The code looks truncated"` → 按实测语义改为「unbalanced braces/parens（V8 报错即此意）——检查 IIFE 前缀 `((` 是否配了 `))` 后缀；代码压短或拆多次 evaluate」。同名 `scan` 不变。
3. **无损性单测**（回应重开评论的验收建议）：构造 >500 字符、含 regex 字面量（`/\n+/g`、`/catal…\//`）与嵌套引号的样本，断言 `_validate_and_fix_javascript(样本) == 样本`（无 LLM 双重转义时不得改写）——把「传输无损」钉进测试；配合既有真实 CDP 形状桩防契约漂移。

**不做**：端到端「>500 字符原样到达并执行」的自动化验收需要真实 LLM 发码，波动大——无损性单测 + 22/22 分类证据已覆盖该关切；`output_config`/SDK 层无关。
